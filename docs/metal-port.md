# Metal port notes

Branch `metal-backend` on baraka1981/VIctory. Goal: run on Apple silicon with a Metal backend we own (not D3DMetal).

## Shape

- victory stays a **Windows program running under Wine** (CPU via Rosetta 2, OS via Wine). Loader TLS patch (`gs:[0x58]`) + `clzero` handler should work unchanged since Wine surfaces SIGILL as a Windows exception. Needs macOS 15+ (Rosetta AVX2).
- GPU: `victory-host` = the seam. `victory-gpu` talks to it instead of D3D12 directly.
  - Windows/PC: `victory-gpu/src/backend.rs` (`D3d12`), pass-through.
  - Mac: `victory-metal`, native arm64 lib. Gets called from the Windows side through a Wine unixlib (`__wine_unix_call`), same trick D3DMetal uses. **Not written yet** — see slice 4.
- Shaders: translator already emits DXIL → feed it to Apple's Metal Shader Converter first. Own MSL/AIR emitter off `ir.rs` later.
- Descriptor tables use MSC's `IRDescriptorTableEntry` layout (24 bytes) so MSC-converted shaders read them as is.

## Done

1. Workspace builds + tests on non-Windows (Linux/macOS). Windows unchanged.
2. `victory-host`: `Device` trait — committed / reserved / placed resources, heaps, allocation info, copyable sizes, descriptor heaps + step. `ResourceDesc` moved there, same layout as `D3D12_RESOURCE_DESC` (offsets tested).
3. victory-gpu production creation paths go through it: host textures (clear values, tiled/reserved), depth twins, small-texture heaps, tile heaps, readback/upload/GPU-upload/shared/UAV buffers, RTV/DSV rings, plane pass, view/sampler heaps, null block, magenta fallback.
4. views + samplers in the seam (`shader_view` / `unordered_view` / `constant_view` / `sampler` / `target_view` / `depth_view` / `copy_descriptors` / `descriptor_start`). Descs are D3D12.X's layouts (`ShaderViewDesc` etc., size/align checked against D3D12's). All 23 production view writes in victory-gpu go through it.
5. `victory-metal`: `Device` on Metal (objc2-metal). Format table (DXGI → MTLPixelFormat, numbers cross-checked vs objc2-metal), D3D12-rules copy layouts, private/shared storage by `Memory`, placement heaps, sparse heaps for reserved textures. Views write MSC-style table entries (buffer: addr/0/len, texture: 0/resource id/0, sampler: id/0/lod bias); texture views via `newTextureViewWithPixelFormat:...`, samplers via `MTLSamplerDescriptor` (argument buffer support on); objects a slot needs are kept alive per slot address; RTV/DSV slots remembered for render passes (`MetalDevice::target`). Portable bits unit-tested on Linux.

6. slice 2a: `Recorder` trait (barriers, buffer/resource/texture copies) + `Device::copy_layout` (full footprints). D3D12: `backend::D3d12List`. Wired: submission preludes (`record_transitions`) and depth-twin copies (`record_twin_copy`). Metal: `MetalRecorder` (command buffer + blit encoder; transitions no-op, UAV barrier ends encoder), GPU round-trip test buffer -> texture -> buffer.

7. slice 3a: `ShaderCode` (DXIL / MSL / metallib), `ComputeDesc` (constants at param/index 0, one buffer per binding after), `Device::compute_pipeline`, `Recorder::dispatch`. D3D12: root signature + compute PSO from DXIL. Metal: pipelines from MSL or metallib, compute encoder per dispatch; GPU test runs a real kernel. DXIL on Metal refused until 3b.

8. slice 3b started: `irconverter.rs` loads `libmetalirconverter.dylib` at run time (saxaboom crate; `VICTORY_IRCONVERTER` overrides the path), converts DXIL compute shaders to a metallib (entry renamed `victory_main`, group size from reflection). Converted pipelines (`Abi::Converted`) get a top-level argument buffer at index 2: constants inline, then one 64-bit address per binding; bound buffers made resident with `useResource`. Mac test `converted_dxil_runs_on_the_gpu` (fixture `tests/fixtures/add.dxil`, dxc v1.8.2505 from `add.hlsl`) **passes on the MacBook (27 Nov)**: conversion, reflection group size, and the top-level argument buffer layout (constants inline, then 8-byte-aligned addresses) are confirmed for this model.

9. slice 3b step 1, root signatures: `victory_host::root` parses serialized D3D12 root signatures (1.0 / 1.1, DXBC container or bare `RTS0`; byte-exact `serialize` too), unit-tested on Linux against dxc-built blobs (`root::samples`, from `victory-host/tests/fixtures/root_signatures.hlsl`). `ComputeDesc` contract now: walk the root signature's parameters in order, root constants take the next N constants, root CBV/SRV/UAV the next binding (tables: step 2); empty `root_signature` = the DXIL's embedded one. D3D12 (`D3d12List::dispatch`) follows it too. Metal: `irconverter::root_signature` builds `IRVersionedRootSignatureDescriptor` (version kept), set as the compiler's global root signature (embedded one ignored); `toplevel::TopLevel` lays out the top-level argument buffer per parameter (constants 4-aligned inline, root descriptors and tables 8-byte addresses). Mac tests: `separate_root_signature_runs_on_the_gpu` (`swap.dxil`, root signature stripped, handed in: UAV, constants(2), SRV), `irconverter_layout_matches` (our offsets vs MSC's `resource_locations()` for RS10 / RS11 / swap). **MacBook, 27 Nov:** separate root signature passes on the GPU. MSC refuses version 1.0 descriptors ("Unsupported root signature version"), so `irconverter::root_signature` always hands it 1.1 via `RootSignature::to_v1_1` (D3D12's reading of 1.0: root descriptors DATA_VOLATILE, ranges DESCRIPTORS_VOLATILE | DATA_VOLATILE, sampler ranges DESCRIPTORS_VOLATILE); Re-run: MSC's offsets for RS10 equal ours (constants 0, CBV 16, SRV 24, UAV 32, table 40); MSC reports tables with space/slot 0xffffffff, so the test matches them by order. **Static samplers take one more top-level entry**, an 8-byte address after the last parameter (RS10: 56; constants(3) + static only: 16; gone without static samplers): `TopLevel::statics`. Each converted pipeline builds `StaticSamplers` (MTLSamplerStates + a shared table of sampler entries, in root signature order), fills that address and makes the table resident. **Confirmed on the MacBook (27 Nov):** two static samplers still take one entry (56); `static_sampler_samples_on_the_gpu` (sampler.hlsl, point + clamp over a 4x1 texture) passes. **All 32 victory-metal tests pass on the Mac: slice 3b done.**

10. slice 3b step 2, descriptor tables: seam `Table { heap, first }`, `Recorder::dispatch(.., tables, ..)` (`Recorder::DescriptorHeap`). D3D12: `SetDescriptorHeaps` with the tables' heaps, `SetComputeRootDescriptorTable(heap GPU start + first * step)`. Metal: the table's top-level entry is `heap buffer GPU address + first * 24` (our `IRDescriptorTableEntry` heaps as is). Residency: root descriptors' buffers, each table's descriptor buffer (`useResource`, read), then every slot the root signature's ranges reach from `first` (`TopLevel::reached`, unbounded = to the heap's end, clipped): placed resources by `useHeap` once per heap, the rest by `useResource` (read-write when an unordered view names it; texture views go by their parent). Slots now keep the buffers buffer views name (BTreeMap by slot address, so a table's slots are a range query); constant views find their buffer by GPU address among buffers the device made (weak refs). Mac test `descriptor_table_runs_on_the_gpu` (`table.dxil`: SRV + UAV + CBV in one table at slot 5, input placed in a heap). **Passes on the MacBook (27 Nov).**

11. slice 3b step 3, graphics pipelines: seam `GraphicsDesc` (`Geometry::Vertex { shader, inputs }` or `Geometry::Mesh { amplification, shader }`, optional pixel `Stage`, root signature as for compute, target / depth formats, samples, topology type, per-target `Blend`, `Raster`, `DepthTest`), `Device::graphics_pipeline`, `Recorder::draw(pass, pipeline, arguments, vertices, draw)` / `draw_mesh(.., groups)`; `Pass` = RTV / DSV slots (+ optional clears), viewport, scissor. Vertex strides come with the vertex buffers per draw (D3D12's way). D3D12: VS+PS PSO, `OMSetRenderTargets` + clears, IA setup, `DrawInstanced` / `DrawIndexedInstanced`, `DispatchMesh`; mesh *pipelines* on D3D12 are `E_NOTIMPL` (needs a pipeline state stream). Metal (`render.rs`): every stage converted with one global root signature (given, else the VS/MS's embedded); vertex descriptor from the input layout (`vertex.rs`: DXGI -> `MTLVertexFormat`, append-aligned offsets, semantic -> MSC stage-in attribute via reflection), buffers at 6 + slot with dynamic strides; mesh -> `MTLMeshRenderPipelineDescriptor` (amplification = object stage, payload from reflection); depth-stencil state object; one render encoder per draw; top-level argument buffer on each stage the pipeline has, residency with `useResource/useHeap:stages:`; MSC draw params (`IRRuntimeDrawArgument`/`IndexedArgument` at 4, index type u16 at 5) when the VS needs them. Mac tests: `vertex_pixel_pipeline_draws` (quad_vs/quad_ps: clear + non-indexed left half, then indexed right half with a load), `mesh_pipeline_draws` (mesh.hlsl + quad_ps), `vertex_formats_match_metal`. **All pass on the MacBook (27 Nov)**, VS+PS and mesh draws included.

12. slice 3c (title pipelines onto the seam), step 1: `victory_host::dxbc` computes the DXBC container checksum (D3D's MD5 padding, as dxc's `ComputeHashRetail`), so `RootSignature::serialize` gives byte for byte what D3D12's serializer and dxc give (matches the RS10/RS11 samples and every signed `.dxil` fixture). `pipeline/host.rs` builds the title root signatures as `victory_host::root::RootSignature` and serializes them itself: no `D3D12SerializeVersionedRootSignature` on that path any more, and the Metal backend can take the same blob. (Same bytes as before, so pipeline library names don't change.)

13. slice 3c step 2, directly indexed heaps: `Arguments` (now also what `dispatch` takes) gains `views` / `samplers`, the heaps `ResourceDescriptorHeap[]` / `SamplerDescriptorHeap[]` index. D3D12: they join the tables' heaps in `SetDescriptorHeaps`. Metal: their tables bind at MSC's descriptor heap points, buffer 0 (views) and 1 (samplers), on every stage the pipeline has; every populated slot of them is made resident (a range query over the heap's slots). Mac test `directly_indexed_heaps_on_the_gpu` (heap.hlsl, cs_6_6: texture, output and sampler by heap index). **Passes on the MacBook (27 Nov); all 33 victory-metal tests green after steps 1-4.**

14. slice 3c step 3, title compute pipelines through the seam: `ComputeDesc::cache` (a name the backend may store/load the compiled pipeline under; D3D12: the pipeline library, same names as before; Metal: ignored for now, `MTLBinaryArchive` later). `HostPipeline::new`'s compute path calls `D3d12::compute_pipeline` with the title DXIL and `root_blob` (the serialized root signature; graphics still create theirs directly, step 4). `pipeline::library` is `pub(crate)` for the backend.

15. slice 3c step 4, title graphics + mesh pipelines through the seam: `GraphicsDesc` carries all of a title pipeline's state in D3D12's terms (stencil faces and masks, sample mask / quality, strip cut, independent blend, logic ops, alpha to coverage, multisample / AA lines / forced samples / conservative raster, depth bounds, an optional geometry shader, a cache name); `Pass` the stencil reference and blend factor. `HostPipeline::new` converts its kept `GraphicsState` (`seam_blend` / `seam_raster` / `seam_depth` / `seam_inputs`) and calls `graphics_pipeline` -> `D3d12::graphics_pipeline`, which builds the **same** D3D12 descriptions as before (plain desc; `DEPTH_STENCIL1` stream for depth bounds, with or without the rectangle GS; mesh stream naming a triangle topology) under the same library names, so stored pipelines keep loading. D3D12 mesh pipelines work now (amplification still `E_NOTIMPL`: victory-gpu makes none). Metal: stencil state, alpha to coverage, non-independent blend = target 0 everywhere, stencil ref / blend colour per draw; geometry shaders refused (the rectangle GS falls back as it does on a D3D12 refusal); logic ops, depth bounds, sample masks, conservative raster warned once and ignored. victory-metal now depends on `tracing`. **D3D12 side type-checked only**: the pipeline library tests (`a_mesh_pipeline_loads_from_the_library`, `depth_bounds_pipeline_loads_and_filters_draws`) need a Windows run.

16. slice 2b step 1, D3D12-style state setting in the seam: `Recorder` gains `set_heaps`, `set_compute_root` / `set_graphics_root`, `set_compute_pipeline` / `set_graphics_pipeline`, `set_root_constants` / `set_root_view` (with its kind: D3D12 sets CBV/SRV/UAV each its own way) / `set_root_table` by `Point` and parameter index, `set_targets` (RTV/DSV slots), `clear_target` / `clear_depth`, `set_viewports` / `set_scissors` / `set_blend_factor` / `set_stencil_ref` / `set_depth_bounds` / `set_topology`, `set_vertex_buffers` / `set_index_buffer` by GPU address (`VertexView` / `IndexView`), `draw_instanced` / `draw_indexed_instanced` / `dispatch_groups` / `dispatch_mesh_groups`; `Device::descriptor_gpu_start` and `gpu_address`. Addresses and descriptor handles are numbers, as in D3D12 (and in MSC's top-level argument buffer). D3D12: pass-through. Metal (`record.rs` rewritten): a state machine. Calls note state; a draw / dispatch brings one open encoder up to date (render encoder kept across draws while targets stay the same: no longer one per draw; compute encoder across dispatches); top-level buffer from per-parameter `Arg`s (`TopLevel::fill_args`); residency from root views' buffers (found by address in the device's `Buffers` registry, shared with the recorder), tables' reached slots (heap found from the handle), whole directly indexed heaps (only when the root signature's flags say so), static sampler tables; vertex / index buffers by address through the registry; clears as render passes of their own (rectangles: whole view, warned). The one-shot `dispatch` / `draw` / `draw_mesh` are built from these calls (our MSL compute apart), so the existing GPU tests now test the state machine. **Not yet run on the Mac.**

17. slice 2b step 2, victory-gpu's title draws through `Recorder`: `HostPipeline` holds the backend's pipeline (`host: D3d12Pipeline`, was `pso` + `root`). `draw.rs` records through the seam (`rec(list)`): heaps, root signatures and pipelines (still cached by object as before), user-data constants, root views (CBV/SRV/UAV incl. ours: memory directory, view addresses, strides, faults), one-view tables, targets, vertex / index buffers (incl. expanded rectangles), topology, viewports, scissors, blend factor (none = D3D12's white), stencil ref, depth bounds, draws, indexed draws, dispatches (incl. split ones and their root words), mesh dispatches. `list.rs` clears go through `clear_target` / `clear_depth`. On D3D12 the same commands are recorded. **Still direct**: indirect execution (`ExecuteIndirect` with D3D12 command signatures, and `indirect.rs`'s FXC-compiled argument clamp), `ResolveSubresource` (no resolve in the seam yet), the FXC helper passes (plane pass, card compare / readback capture in `host.rs`, in-place probe), diagnostics (`capture.rs`).

## Gotchas

- `crates/victory-formats/src/bcpack-tables.bin` comes from `Initialize-FormatTables.ps1` (or curl the pinned Marvisak URL in that script, check the SHA-256); bcpack tests fail without it.
- Residency walks every reached slot per dispatch (a range query, but unbounded bindless tables over a big heap = many `useResource` calls). macOS 15 `MTLResidencySet` on the queue is the likely end state (needs macOS 15 anyway, Rosetta AVX2); `useHeap` already covers placed resources cheaply.
- A buffer stays alive while a descriptor slot names it (slots keep it, for residency): rewriting/clearing slots frees it.
- MSC stage-in attributes start at 11 (`kIRStageInAttributeStartIndex`). `render::vertex_descriptor` uses reflection's attribute indices as is when the Metal function's `vertexAttributes` contain them, else adds 11: `vertex_pixel_pipeline_draws` passes, so one of the two works; which one isn't logged yet.
- Indexed draws with draw params: `startIndexLocation` gets the first index (D3D12's meaning); saxaboom-runtime's port passes the byte offset there. Matters only for shaders reading SV_VertexID-style params.
- MSC is told to ignore the embedded root signature when one is handed in (D3D12: the PSO's wins). Untested with both present and different.
- Metal table entry metadata words follow MSC's runtime header from memory — check vs `metal_irconverter_runtime.h` when shaders run. Typed buffer SRV/UAVs need texture-buffer views (TODO), stencil-plane views too.
- Packed 16-bit formats (B5G6R5, BGR5A1, B4G4R4A4) channel order vs Metal unverified — needs a draw-and-read test.
- No D24S8 on Apple silicon → D32FS8 (same as MoltenVK/D3DMetal).
- 16 KB pages under Rosetta/Wine vs the page-guard + DirectStorage tricks: biggest runtime risk, test early.
- Upstream isn't rustfmt-clean; don't mass-format (rebase pain).
